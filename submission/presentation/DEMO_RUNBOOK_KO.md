# Nimbus Growth Desk 라이브 데모 런북

## 데모 목표

`SEG-0000214 발견 → EXP-0000009 근거 검색 → AI 초안 → 사람 승인 → Lakebase 커밋 → Gateway 비용 확인`을 10분 안에 완주한다.

## 사전 점검 (T-15분)

1. 브라우저를 Databricks workspace에 로그인한 상태로 연결한다.
2. 앱 URL을 연다: `https://nimbus-growth-desk-7474655051393778.aws.databricksapps.com`
3. Gateway 대시보드 URL을 새 탭에 미리 연다: `https://fe-sandbox-last-penguin.cloud.databricks.com/dashboardsv3/01f1a1dd34c41076a3e8815da30f2fd4/published?isDbOne=true&utm_source=nimbus-growth-desk`
4. 앱 헤더에 로그인 사용자, 첫 화면에 `SEG-0000214`, 2.9% vs 4.2%, 420K, $524.2K, +1.80%p, $721.3K가 보이는지 확인한다.
5. 필요하면 **초기화 → 확인하고 초기화**를 누른다. 이 동작은 해당 세그먼트의 앱 의사결정 행만 삭제하며 동기화 원본은 변경하지 않는다.

## 라이브 동선 (10분)

### 0:00-1:30 — 문제와 근거

- `SEG-0000214`의 전환율과 위험 매출을 짚는다.
- `EXP-0000009 +2.25%p`와 세 후보 액션을 보여준다.
- 하단 출처에서 Lakebase BM25 검색과 읽기 전용 동기화 원본을 언급한다.

### 1:30-4:00 — 조사·AI 초안

- **근거 검색 + 초안**을 누른다.
- 로딩 상태가 보이는 동안 “AI는 승인하거나 커밋하지 않는다”고 말한다.
- 결과에서 **AI 생성 결과**, **사람 승인 필요**, 출처, decision ID를 짚는다.

### 4:00-6:00 — 사람 승인

- **25% 롤아웃 승인**을 누른다.
- 로그인 사용자가 `approved_by`로 기록되고 상태가 “사람 승인 완료”로 바뀌는 것을 확인한다.

### 6:00-7:30 — Lakebase 커밋

- **결정 커밋**을 누른다.
- 같은 decision ID가 유지되고 감사 이력이 proposed → approved → committed로 누적되는 것을 확인한다.

### 7:30-10:00 — Gateway 비용

- **Gateway 대시보드**를 누른다.
- 추정 비용, 요청 수/토큰, 403 차단, $0.03/$0.05 임계값을 짚는다.
- 요청 로그에서 application, requester, request ID를 짚는다.
- 외부 모델 실제 spend가 없을 때 0달러가 아니라 NULL/미제공으로 표시된다는 설명으로 끝낸다.

## 실패 시 복구

- 앱 로딩 실패: 새로고침 1회 후에도 실패하면 PPT 4·6·8번 슬라이드로 핵심 사례, 결정 체인, Gateway 결과를 설명한다.
- AI 호출 403: “Gateway가 비용/정책으로 멈춘 실제 결과”로 전환하고 대시보드의 403 행을 보여준다.
- 검색 결과 없음: `EXP-0000009` 카드와 읽기 전용 원본 설명을 사용하고 API 호출을 재시도하지 않는다.
- 대시보드 지연: 게시 탭을 새로고침하고 최근 요청 로그로 바로 이동한다.
- 절대 하지 않을 것: Gateway 등록·정책·예산 설정 화면 시연, 다른 세그먼트 데이터 삭제, 동기화 원본 수정.
